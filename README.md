# Desktop Media Player

Десктопный медиаплеер на Tauri v2 + React + Rust для Windows. Демонстрирует построение лёгкого нативного приложения с потоковым воспроизведением аудио, дисковым кэшированием, офлайн-режимом и интеграцией с системными API (SMTC, Discord RPC).

## Стек

- **Frontend:** React 18, TypeScript, Vite
- **Backend:** Rust, Tauri v2 (IPC между frontend и backend)
- **Стили:** Vanilla CSS (CSS Custom Properties, Flexbox/Grid)
- **Ключевые зависимости (Rust):**
  - `reqwest` — HTTP-клиент для запросов к API
  - `tauri-plugin-keyring` — хранение токенов через Windows Credential Manager
  - `souvlaki` — интеграция с System Media Transport Controls (SMTC)
  - `discord-rich-presence` — IPC-клиент для Discord
  - `tokio` — асинхронный I/O для скачивания файлов
  - `serde`, `serde_json` — парсинг и сериализация JSON

## Функционал

### Интерфейс

- Тёмная тема: чёрный/тёмно-серый фон, фиолетовый акцент
- Навигация вкладками без фоновых плашек (Моя музыка, Поиск, Скачанные, Плейлисты, Микс); активная вкладка выделяется нижним подчёркиванием
- Кастомные SVG-иконки, без эмодзи
- Range-слайдеры прогресса и громкости: заливка через динамический `linear-gradient`, бегунок виден только при наведении
- Skeleton loading для списков
- Сохранение позиции скролла при переключении вкладок (`useRef`)
- Аккордеоны для секций «Плейлисты» и «Подборки»
- Мини-плеер: вертикальное окно Always-on-top, перетаскивание за любую область (`-webkit-app-region: drag`), обложка растягивается через `flex: 1`, вертикальный ползунок громкости (`writing-mode: vertical-lr`)

### Управление треками

- Hover-меню действий на строке трека (без контекстного меню ПКМ)
- Кнопка управления кэшем с тремя состояниями: скачать → загрузка → удалить
- Лайки с оптимистичным обновлением UI (трек сразу появляется в «Моей музыке» без перезагрузки)
- Копирование строки `Artist - Title` в буфер обмена
- Бесконечная пагинация по 50 элементов во всех динамических списках
- Кнопка Previous с правилом 5 секунд: при `currentTime > 5` — перемотка в 0, иначе — переход к предыдущему треку

### Кэш и офлайн-режим

- Автоматическое фоновое скачивание при воспроизведении, включая автопереход
- Атомарная запись: сначала во временный `.tmp`, затем переименование в `.mp3`
- Дедупликация активных загрузок через стейт `downloadingTracks`
- Синхронизация при старте: backend сканирует `AppData`, метаданные подтягиваются из `localStorage`
- Вкладка «Скачанные» с кнопкой ручной синхронизации

### Системная интеграция

- SMTC (Windows): системный оверлей и перехват мультимедийных клавиш
- Discord Rich Presence: `ActivityType::Listening`, обложка, название, временные метки `start`/`end` для живого прогресс-бара
- Мини-плеер: аудиопоток не прерывается при смене режима окна

## Архитектура

Разделение ответственности: frontend отвечает за UI и состояние, backend — за сеть, файловую систему и системные вызовы.

**Авторизация.** Прямой вход по логину/паролю для сторонних приложений недоступен, используется ручной ввод токена. Frontend передаёт токен в Rust-команду `save_token`; backend валидирует его, сохраняет в Windows Credential Manager и возвращает статус. Все последующие запросы к API выполняются на стороне Rust с извлечением токена из хранилища.

**Загрузка данных.** React вызывает Rust-команды (`get_my_music`, `get_playlist_tracks`, `search_music`, `get_recommendations`). Rust формирует запросы, парсит JSON, маппит в структуры `AudioItem` и `Playlist`, возвращает во frontend. Для плейлистов реализован fallback: при отсутствии `owner_id` в ответе API выполняется дополнительный запрос для получения ID текущего пользователя.

**Воспроизведение.** HTML5 `<audio>` размещён на корневом уровне React-дерева — это исключает обрыв воспроизведения при смене вкладок и режимов. Перед воспроизведением проверяется наличие локального файла: при наличии используется протокол `asset://`, иначе — прямой URL. Актуальное состояние кэша хранится в `useRef` (`downloadedTracksRef`) во избежание повторного ре-рендера тега `audio`.

**Системные интеграции.** SMTC и Discord RPC инициализируются в Rust в главном потоке (привязка к HWND окна). Мультимедийные клавиши эмитят события через Tauri Event Bus; frontend обрабатывает их и вызывает соответствующие функции плеера. Инициализация SMTC контролируется во избежание повторного вызова `init_media_controls` при смене режима окна.

**Content Security Policy.** В `tauri.conf.json` настроены `img-src` и `media-src` с разрешениями `https:`, `http:`, `asset:`; активирован `assetProtocol` со scope на `$APPDATA` для доступа к локальным файлам.

## Сборка и запуск

Требования:

- Node.js (LTS)
- Rust (через rustup)
- Microsoft C++ Build Tools с нагрузкой «Разработка классических приложений на C++»
- WebView2 Runtime (на Windows 11 установлен по умолчанию)

```bash
git clone https://github.com/your-username/media-player.git
cd media-player
npm install
npm run tauri dev
npm run tauri build
```

Готовые файлы релизной сборки — в `src-tauri/target/release/bundle/`.

## Настройка Discord (опционально)

1. Создать приложение в Discord Developer Portal.
2. Скопировать Application ID.
3. Указать его в `src-tauri/src/lib.rs` в константе `DISCORD_APP_ID`.

Без этой настройки модуль Rich Presence неактивен.

## Конфигурация API и авторизация

Для загрузки медиатеки требуется access token к API медиасервиса. Токен должен быть получен официальным способом, предусмотренным документацией сервиса. Использование сторонних генераторов токенов и обходных методов получения может нарушать условия использования сервиса.

Порядок настройки:

1. Получить токен в соответствии с правилами выбранного медиасервиса.
2. Ввести токен в поле авторизации при первом запуске.
3. Токен сохраняется в Windows Credential Manager и в дальнейшем запрашивается только на стороне backend.

Требования к токену: наличие прав на доступ к аудио и offline-режим (если предусмотрено API). При генерации токена и первом запуске не использовать VPN, если это противоречит правилам сервиса.

## Известные проблемы и решения

| Проблема | Решение |
|---|---|
| API не возвращает `owner_id` для плейлистов (`owner_id is undefined`) | Fallback-запрос на получение ID текущего пользователя |
| Обрыв воспроизведения при фоновом скачивании | `src` тега `audio` обновляется только при смене трека через `downloadedTracksRef` |
| Параллельные загрузки одного трека при быстрых кликах | Блокировка через стейт `downloadingTracks` |
| Битые файлы при обрыве сети | Атомарная запись через временный `.tmp` с последующим переименованием |
| Пустая вкладка «Скачанные» после очистки кэша браузера | Сканирование `AppData` при старте + кнопка ручной синхронизации |
| Зацикливание очереди при бесконечной пагинации | Синхронизация массива `queue` с текущим списком |
| Race condition при обновлении рекомендаций | Request ID и флаг загрузки |
| Краш при переходе в мини-плеер из-за двойной инициализации SMTC | Удалён дублирующий вызов `init_media_controls` |
| Ползунок громкости выходит за границы окна в мини-плеере | Переработан CSS: `flex: 1` для обложки, `writing-mode: vertical-lr`, выравнивание по нижнему краю |
| Отсутствие обложек и звука в релизной сборке | Добавлены разрешения CSP в `tauri.conf.json` |
